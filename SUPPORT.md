[Helpin documentation](https://helpin.ai/docs) (coming soon). Until then, use the

- [Install Community](community/README.md).

## Questions, bugs, and feature requests

Search [existing issues](https://github.com/helpin-ai/helpin/issues) before opening
a new one. For setup questions, use an issue with a descriptive title and explain
which documented step failed. For reproducible failures, use the
[bug report form](https://github.com/helpin-ai/helpin/issues/new?template=community-bug.yml).
For proposed improvements, use the
[feature request form](https://github.com/helpin-ai/helpin/issues/new?template=community-feature.yml).

Include your Helpin release or commit, Community/EE edition, OS and CPU
architecture, installation method, expected behavior, and minimal reproduction
steps. Include only relevant, redacted log excerpts. Remove credentials, session
tokens, signed URLs, personal information, and customer content. Never attach
`.env`, database dumps, or raw support archives.

Community support is best effort; no response deadline or service-level agreement
is promised. Community 0.1 is beta: see [known limitations](ROADMAP.md) and the
[supported security version policy](SECURITY.md). Repository issue access and
published releases remain subject to the [publication gates](community/PUBLICATION.md).

## Security vulnerabilities

Follow [SECURITY.md](SECURITY.md) for private vulnerability reporting. Do not post
exploit details or sensitive data in public issues.

## Contributions

Read [CONTRIBUTING.md](CONTRIBUTING.md) before submitting changes. Product guides
will be hosted in Helpin; technical instructions stay versioned with the code. Report
incorrect documentation with the page URL, affected version, and the step that
needs correction.
