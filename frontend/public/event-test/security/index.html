Security is a system, not a badge wall.

Opening this route emits a procurement pageview and an article_view for security-overview. Scroll to 75% to exercise the versioned interaction milestone.

Boundaries before features.

Workspace identity is derived from authenticated installation credentials. Payload-supplied project identifiers are discarded before the event reaches Kafka.

  1. Tenant binding

    Every captured event carries the workspace from the matched browser or server credential.

  2. Evidence provenance

    Anonymous, claimed, and cryptographically verified identities remain visibly distinct.

  3. Bounded retention

    The local behavioral store declares a 400-day TTL and evaluator reads stay time-bounded.

Operational controls

Failures should be inspectable.

Kafka exposes raw, enriched, dead-letter, and sessionized stages. Capture falls back to disk when delivery is retryable, and a replay worker drains recovered segments.

A claimed browser identity remains untrusted in the Rust capture boundary. That is expected until signed widget identity is enabled.

Procurement note

No mystery tenant field.

The test application never sends a project ID. The value visible in ClickHouse is created only by token authorization, which makes this page useful for both behavioral and isolation testing.
