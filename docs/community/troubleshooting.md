# Troubleshoot Community installations

This guide applies to the Community Docker Compose bundle. Run commands from its
`community/` directory. For source builds, first complete the
[source-build guide](https://github.com/helpin-ai/helpin/blob/develop/docs/community/development.md).
A hosted help center for product workflow guides is planned; this guide covers
installation and service problems.

## Start with service status

```sh
./setup.sh status
docker compose --env-file .env -f compose.yaml logs --tail=100 helpin-api helpin-migrate
```

Status lists containers, image identities, and migration information. The migrator,
Temporal schema, and namespace jobs are one-shot jobs: an exit code of zero is
expected. A restarting service or nonzero job exit needs investigation.

Read the failing service's logs before restarting anything. Review excerpts before
sharing them; logs can contain customer data. Do not publish `.env`, full Compose
configuration, credentials, signed attachment URLs, or database backups.

## Images cannot be pulled or built

**Symptoms:** registry access denied, unknown manifest, or missing Runtime source.

The candidate is unpublished until release gates pass. Do not assume candidate
image tags are publicly pullable. Use an actual published bundle, or build from
source with access to both repositories and the pinned Runtime revision. See the
[installation guide](../../community/README.md). Source builds need more resources
than the evaluation baseline of 8 GB RAM and 20 GiB disk; inspect Docker build
output for resource exhaustion before retrying.

## Dashboard cannot reach the API

1. Check `./setup.sh status` and the API/migrator logs above. API startup waits for
   successful migrations and infrastructure readiness.
2. On the installation host, open `http://localhost:8085`. From another computer,
   `localhost` refers to that computer, not the installation host.
3. For public access, check DNS, HTTPS, and reverse-proxy routing. Keep the default
   internal services private; use the [deployment guide](deployment.md).
4. Check `APP_BASE_URL` matches the dashboard's public origin. The bundled
   frontend uses same-origin `/api`; setting a runtime `VITE_API_URL` does not
   reconfigure the prebuilt JavaScript.

After correcting `.env`, run `./setup.sh start` to apply the configuration. Do not
regenerate encryption keys to fix connectivity.

## Widget is missing or visitor requests return 403

1. In workspace settings, add the website origin, including scheme, hostname,
   and port. An empty allowlist rejects visitor requests. Add preview and
   help-center origins separately when those pages embed chat.
2. Copy the current generated installation snippet. Verify its SDK and widget
   URLs point to this installation, not a previous host.
3. In browser developer tools, check whether the loader downloads and whether
   requests fail due to an origin rejection, Content Security Policy, or mixed
   HTTP/HTTPS content. Allow the configured origins in your site's CSP as
   described in the [deployment guide](deployment.md).
4. Check workspace identity configuration when identification fails. A copied
   public installation key is not authentication. See [widget identity](widget-identity.md).

Retest from the actual website origin. Do not disable origin or identity checks as
an installation workaround.

## Messages arrive only after refresh or chat disconnects

Check the edge proxy preserves WebSocket Upgrade/Connection headers, disables
stream buffering, and uses the documented timeout. Then inspect API and NATS logs:

```sh
docker compose --env-file .env -f compose.yaml logs --tail=100 helpin-api nats redis
```

NATS and Redis must be healthy in the supported bundle. Verify normal HTTP replies
as well as live updates after correcting the proxy. The [deployment guide](deployment.md)
contains the required public routing and trusted-proxy settings.

## Support agent does not respond

1. In Settings → AI, configure a shared connection and profile, then choose a
   workspace default. A profile name alone does not supply credentials.
2. Check the selected model and provider credentials. A local/compatible model
   endpoint must also be approved in Runtime's app configuration.
3. Check Runtime API, Runtime worker, Helpin API, and NATS status/logs:

```sh
docker compose --env-file .env -f compose.yaml logs --tail=100 helpin-api agent-runtime agent-runtime-worker nats
```

Helpin's API consumes Runtime execution events. If Runtime progresses but Helpin
looks stuck, investigate the API's projection consumer and shared NATS connection.
The Helpin worker is not the agent executor. Preserve the Helpin/Runtime secret
pair and internal callback configuration generated by the installer; there is no
in-process fallback. See [AI configuration](configuration.md).

## Knowledge search or help-center AI is unavailable

Agent profiles do not configure embeddings or every AI feature. Embeddings need
separate server settings and 1,536-dimensional vectors. Without embeddings,
retrieval uses keyword matching. Check the server configuration and Helpin worker
logs for indexing failures; verify the article has been published for public use.
Help-center AI answers and triage also have separate server-level provider
settings. See [configuration](configuration.md).

## Invitation or password-reset mail does not arrive

Check application SMTP configuration, sender address, provider delivery logs,
and API errors. SMTP credentials require TLS and AUTH PLAIN; LOGIN-only servers
are unsupported. Without application mail, local signup can work while invitations
and password reset cannot send. Support email replies and inbound mail use the
optional Postmark integration; application SMTP does not enable those channels.
See [mail configuration](configuration.md).

## Attachments fail to upload or display

Check Garage health and `PUBLIC_STORAGE_URL`. The URL used by the browser must
be reachable over HTTPS on a public installation. Inspect browser request errors,
proxy routing, and CSP rules. Private attachments use signed URLs; do not make the
bucket public to bypass an authorization or URL configuration problem.

## Migration or restore fails

Keep the failing migration version and redacted error text. Do not edit applied
SQL, reset the migration ledger, or delete volumes as a repair shortcut. Clean
installation and same-release restore are supported. `helpin upgrade` moves only
to a release that declares a tested upgrade path from the installed tag; see
[upgrade an installation](cli.md#upgrade-an-installation). A previous image alone
does not undo a schema change.
Use the [backup and restore guide](backups.md) with the matching databases, object
storage, bundle, and encryption keys.

## Ask for help

Use the [support guide](https://github.com/helpin-ai/helpin/blob/develop/SUPPORT.md)
for reporting details and contact routes. Vulnerabilities belong in the private
